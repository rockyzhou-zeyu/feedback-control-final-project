16-299 Final Project

Snowboard Carving Control With a Weighted Hip Joint

A planar carving simulator, a physically interpretable rider model, and a saturation-limited LQR controller for tracking a downhill carve through disturbances.

0.202 m default RMS lateral error
17.5° default peak effective edge angle
96.5 Nm default peak hip torque
3 slope and disturbance presets

Abstract

This project studies a snowboard-inspired trajectory tracking problem: can a simplified rider-board system follow a desired carving path while staying stable under limited actuation, terrain variation, and disturbances? I built a planar simulation in Python and a browser visualization that show the reference path, realized path, rider posture, control input, and disturbance signals. The model has eight states: downhill and cross-slope position, heading, speed, lower-body roll angle and roll rate, and torso hip angle and hip rate. The controller is a discrete-time LQR with an added integral state for lateral tracking error, feedforward shaping from the reference curvature, and hard saturation on hip torque. In the default all-mountain scenario, the controller tracks the carve with 0.202 m RMS lateral error, 17.5 degrees peak effective edge angle, and 96.5 Nm peak torque while remaining within the modeled roll and hip limits.

Introduction and Motivation

Snowboarding is interesting as a control problem because the goal is not merely to stay upright. A rider must choose a moving line, create edge angle, manage speed, and recover when snow or body motion pushes the board away from the intended path. A fully realistic snowboard simulator would require three-dimensional multibody dynamics and detailed snow-edge contact mechanics. That would be valuable, but it would also make the project difficult to tune and evaluate in one semester. I therefore chose a control-oriented abstraction that keeps the essential feedback problem visible: a rider follows a smooth downhill carve using hip torque while the simulated board experiences reduced grip, a gust-like roll upset, and a short yaw upset.

The final deliverable has two parts. The Python package in snowboard_sim/ contains the dynamics, controller, simulation loop, metrics, and data export. The static browser demo in web/ renders the resulting trajectories and telemetry with HTML canvas animation. This split made iteration fast: the model can be regenerated with one Python command, and the visualizer can be opened directly in a browser or served by GitHub Pages.

Planar Rider and Carving Model

The model is intentionally planar. The state is [x, y, psi, v, phi, phi_dot, eta, eta_dot], where x is downhill position, y is cross-slope position, psi is heading, v is speed, phi is lower-body and board roll, and eta is the torso angle relative to the lower body. The reference path is a smooth sinusoidal carving line y_ref(x), so desired heading and curvature come from path geometry instead of a manually prescribed steering signal.

The central modeling choice is the effective edge angle: theta_eff = phi + alpha eta. The coefficient alpha is computed from the upper-body center-of-mass contribution relative to the total rider-board moment. This gives the hip joint a real role in the simulation. Torso articulation is not cosmetic; it changes the edge angle used in the curvature law and feeds back into roll through the hip-to-roll stiffness term. The carve curvature is kappa = grip g tan(theta_eff) / v^2, which captures three useful effects: higher edge angle turns more sharply, higher speed reduces curvature for the same edge angle, and poor grip weakens edge authority.

The roll equation includes gravitational restoring stiffness, damping, hip coupling, terrain roll moment, and a gust impulse. The hip equation includes commanded torque, damping, passive hip stiffness, and cross-coupling from roll. State limits clip speed, lower-body roll, and hip angle to keep the simulated motion inside the intended physical range. The result is not a high-fidelity snowboard mechanics model, but it is a coherent control plant with interpretable mass distribution, actuation limits, and disturbance channels.

The disturbance model separates effects that happen in different ways. The low-grip patch is spatial, so the board sees reduced edge authority only while its downhill position is inside that section. The gust and edge upset are time-localized impulses: one enters the roll dynamics and the other enters heading. This split made validation easier because a recovery that works for the gust does not automatically prove that the controller handles reduced snow grip. The dynamics are integrated with fourth-order Runge-Kutta at 0.02 s, which is small enough for smooth browser playback and stable enough for comparing tuning changes across scenarios.

Controller and Implementation

The controller is a saturation-limited LQR built around a linearized tracking model. I used a seven-state augmented controller state: integral of lateral error, lateral error, heading error, roll error, roll-rate error, hip-angle error, and hip-rate error. The continuous linear model is discretized at the simulation time step of 0.02 s. The feedback gain is computed by solving the discrete algebraic Riccati equation, with larger weights on heading, lateral error, and hip-rate regulation and a scalar penalty on torque.

A pure feedback controller initially worked on gentle turns but produced unnecessary torque during sharper sections of the reference. The final version therefore computes a feedforward posture from the path curvature, then uses LQR feedback to reject errors around that posture. The raw torque command is clipped to +/-120 Nm. When clipping occurs, the integral state is slightly relaxed so the controller does not keep winding up against an unreachable torque. This simple anti-windup step was enough for the current disturbances and made the browser telemetry easier to interpret.

The LQR is local rather than globally optimal: it is tuned around the nominal speed and the simplified linear tracking model, then tested in the nonlinear simulator. I treated the controller as successful only if the nonlinear run stayed inside posture limits while tracking the moving path. This was important because a controller can reduce lateral error by asking for unrealistic edge angles or by sitting at the torque limit. The final tuning therefore penalizes heading error and lateral error strongly, but also keeps enough penalty on hip-rate error and torque that the simulated rider remains plausible.

The implementation lives in three main files. model.py defines the physical parameters, reference state, disturbances, dynamics, and fourth-order Runge-Kutta integration. controller.py constructs the tracking model and LQR gain. pipeline.py runs scenarios, computes metrics, and exports a JavaScript data bundle consumed by the browser demo. Keeping the simulation export deterministic made it straightforward to compare controller changes across the same disturbance sequence.

Evaluation and Results

I evaluated the controller on three presets. Blue Groomer uses a milder slope, wider turns, and smaller disturbances. All-Mountain Carve is the default balanced case. Steep Technical increases slope pitch, path tightness, and disturbance strength. For each run I report RMS lateral error, peak roll angle, peak hip angle, peak effective edge angle, peak torque, control energy, average speed, and whether roll and hip remain within their modeled limits.

Steep Technical 0.219 m 18.8° 109.7 Nm 8.09 m/s stable

The results are reasonable for the intended model. Error rises as the scenario becomes harder, torque approaches but does not exceed the saturation limit, and the effective edge angle stays below the 28 degree limit. The live demo also validates timing and recovery qualitatively: tracking error spikes near the gust, edge upset, and low-grip region, then returns toward the reference rather than diverging. The browser view was useful because the most important failure modes were visual. If the board crossed the reference at the wrong phase, if torque stayed pinned at saturation, or if hip and roll moved in physically confusing directions, those problems were visible immediately.

The most important limitation of these metrics is that they validate the closed-loop behavior of this model, not real snowboard performance. RMS lateral error measures path tracking, peak torque checks actuator feasibility, and peak edge angle checks whether the rider posture stayed inside the modeled envelope. They do not verify snow contact pressure, front-rear load transfer, or three-dimensional balance. I view the current results as evidence that the control architecture is internally consistent and ready for a more realistic plant, rather than as a claim that the model predicts exact real-world snowboard motion.

Reflections

The main thing that worked was starting with a simple, explainable baseline. Earlier ideas included a richer rigid-body snowboard model and a possible reinforcement learning comparison. Those ideas are attractive, but they would have made debugging harder before there was a trusted plant and metric bundle. LQR was a good match for this stage because it gave a principled feedback controller, exposed the tuning tradeoff between tracking and effort, and made it easy to reason about errors in the linearized coordinates.

The most difficult part was balancing physical meaning against controllability. If hip articulation mattered too little, the torso joint became only an animation detail. If it mattered too much, the simulated rider could steer unrealistically with small torso motions. The current alpha and hip-to-roll coupling are a compromise that keeps the control story legible while preserving bounded posture. Another challenge was evaluation. A single successful animation was not convincing, so I added multiple presets, explicit disturbances, and metrics that can be regenerated from code.

The largest limitation is model fidelity. Snowboard carving depends on edge geometry, contact length, snow deformation, pitch, yaw, and front-rear load transfer. This project compresses those effects into a lumped grip and curvature law. The next best extension would be a sidecut-contact model that computes curvature from board geometry and pressure distribution. After that, gain scheduling or MPC would be natural controller upgrades because the current LQR is tuned around one nominal speed and plant.

Conclusion

The project achieved its baseline objective: it turns a snowboard-inspired physical setting into a measurable trajectory-tracking control problem, implements a controller that behaves sensibly under disturbances, and presents the results through a reproducible simulation and static web demo. The implementation is simple enough to inspect but rich enough to show why rider mass distribution, hip actuation, torque saturation, and snow grip matter. The strongest future path is to keep the current evaluation harness and replace pieces of the plant with more realistic contact dynamics one at a time.
